# KakeFlow v1.3.0

Released 2026-09-02.

## What changed

- Added a read-only Connector Control Center for native source inventory, health and refresh operations.
- Made connector account bindings an explicit posting-authorization boundary, with version and generation fencing against stale or ABA updates.
- Added durable refresh batches, per-source cursors and backoff, fail-closed recovery, and redacted operational summaries.
- Hardened the isolated macOS ARM64 release path with canonical physical paths, atomic locks, source/resource identity digests, and packaged artifact verification.
- Removed two test-only CodeQL data flows at their source and recorded the generated Tauri macro finding separately as a false-positive candidate pending exact-head analysis.

## Install

- PWA: [thangldw.github.io/kakeflow/app](https://thangldw.github.io/kakeflow/app/)
- macOS Apple Silicon: download `KakeFlow_1.3.0_aarch64.dmg` from the [canonical GitHub release](https://github.com/thangldw/kakeflow/releases/tag/v1.3.0).
- Verify the downloaded file against `SHA256SUMS.txt` before opening it.

The macOS community binary is ad-hoc signed and not notarized. The account-free PWA is the supported no-Gatekeeper path.

## Evidence and boundaries

- Frontend, release-contract, Rust, PWA, Poppler and CodeQL gates must pass for the exact release commit before publication.
- Connector tests use synthetic adapters and records. This release does not claim a production bank pilot, direct bank aggregation or Money Forward parity.
- The PWA intentionally has no desktop provider clients, connector credentials or native backup compatibility.
- The documented medium-severity `glib` advisory remains in the Linux Tauri GTK dependency path; the shipped macOS ARM64 artifact does not exercise that path.
- Poppler provides automated visual QA artifacts, not human visual approval.

See [Security](../SECURITY.md), [Operations](../OPERATIONS.md), and the [CodeQL triage record](../evidence/codeql-triage-2026-08-31.md) for the maintained evidence boundary.
