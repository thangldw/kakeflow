# KakeFlow v1.2.1 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish KakeFlow v1.2.1 as an explicitly ad-hoc-signed, non-notarized Apple Silicon community build with a signed Tauri updater archive, checksums, current release documentation, and public verification evidence.

**Architecture:** Keep runtime behavior unchanged. Align all release metadata and public CTAs to 1.2.1, build the macOS app and DMG locally with Apple ad-hoc signing plus the existing non-Apple updater key, then publish only after exact-tree CI and artifact validation pass.

**Tech Stack:** Tauri 2, Rust 1.97, Node.js 22, Vite, Vitest, GitHub Actions, GitHub Releases.

**Spec:** `docs/superpowers/specs/2026-08-24-kakeflow-phase2-hardening-design.md`

## Global Constraints

- The PWA remains the no-Gatekeeper public option; the macOS DMG is a community build.
- The macOS application is ad-hoc signed and not Apple-notarized; never describe it as a frictionless production installer.
- Keep the updater private key outside the repository and publish only the updater archive, its signature, `latest.json`, the DMG, and SHA-256 checksums.
- Publish only Apple Silicon (`aarch64`) macOS artifacts for v1.2.1.
- Do not dismiss the Linux-only `glib` advisory; preserve its explicit affected-path assessment.
- Do not change accounting, OCR, storage, migration, updater, or PWA behavior in this release task.
